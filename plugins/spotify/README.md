# Spotify Connect для Alice Homebrew

Версия `2.0.0-beta.1`. Приёмник Spotify Connect для Яндекс Станции Мини 1 (YNDX-0004) на официальном клиенте Spotify: [Spotify Soloist](https://developer.spotify.com/documentation/soloist). Нужны Homebrew 0.7.0 или новее, готовый ADB root, **Spotify Premium** и **свой API-ключ Soloist**.

**На колонке пока не проверялся.** На ПК тот же Soloist с ключом вошёл в аккаунт и воспроизвёл треки без ошибок. Скачивание, runtime и запуск плагина проверены на arm64 под qemu. Звук через заглушку PulseAudio ещё ждёт проверки на устройстве.

## Как пользоваться

1. Создайте ключ: войдите на [developer.spotify.com/dashboard/soloist](https://developer.spotify.com/dashboard/soloist) аккаунтом с Premium, примите условия, если попросят, и нажмите **Generate API Key**.
2. Установите плагин в Homebrew, откройте «Настроить», вставьте ключ в поле «API-ключ Spotify Soloist» и нажмите «Сохранить настройки». Ключ хранится только на колонке и в браузер не возвращается: после сохранения поле показывает «Ключ сохранён на колонке». Заменить ключ — вставить новый и сохранить; «Удалить» стирает его.
3. Включите плагин. При первом запуске колонка сама скачает Soloist с сервера Spotify, около 13 МБ.
4. Телефон или компьютер со Spotify должен быть в той же сети, что и колонка. В Spotify нажмите значок устройств и выберите `Alice Mini` (или ваше имя). Вход сохраняется в данных плагина и переживает перезапуск.

Звук идёт через штатный `aplay` и микшер `dmixer` Алисы, как у AirPlay: Алиса продолжает слышать и отвечать. Пока она слушает, думает или отвечает, музыка плавно приглушается (по умолчанию до 20 %). Плагин читает только состояние Алисы из её локального сокета событий `127.0.0.1:9875`, но не распознанные фразы. Пока играет Spotify, данные о звуке доступны плагинам с разрешением `audio.levels`, например «Звуковому кольцу».

## Как это устроено

- **Soloist в пакет не входит.** Spotify запрещает распространять его бинарник, поэтому плагин скачивает текущую сборку с `soloist-builds.spotifycdn.com` по HTTPS, проверяет, что это arm64 ELF и что `soloist --version` запускается.
- **Обновления.** Каждая сборка Soloist работает 90 дней. Плагин проверяет новую сборку раз в 12 часов и подменяет её, когда минуты две ничего не играет, чтобы не оборвать песню. Если сборка всё же истекла (код выхода 10), новая скачивается сразу.
- **glibc.** Soloist нужен glibc 2.38, а на колонке 2.23. Поэтому в плагине есть свой загрузчик и библиотеки glibc 2.41 из Debian 13, и Soloist запускается через них. Прошивка колонки не меняется.
- **Звук.** Soloist выводит звук только в PulseAudio или PipeWire. Вместо них в плагине своя маленькая `libpulse.so.0` ([pulse-shim/pulse.c](pulse-shim/pulse.c)): она отдаёт PCM в именованный канал и применяет громкость Spotify. Сервис плагина читает канал и передаёт звук в микшер Алисы.
- **Место.** Soloist занимает около 34 МБ, во время обновления — две копии. Меньше 100 МБ кэша Soloist не принимает, поэтому плагин сам удаляет старые аудиофрагменты и держит кэш в пределах 16–24 МБ.

## Настройки

| Поле | Значение |
| --- | --- |
| API-ключ Spotify Soloist | Ваш ключ из кабинета Spotify for Developers |
| Имя в Spotify | Как колонка называется в списке устройств, до 32 символов |
| Громкость при первом подключении | Начальная громкость Spotify, 0–100 % |
| Громкость, пока говорит Алиса | Уровень музыки во время разговора с Алисой; 100 — не приглушать |

## Ограничения

- Нужен Premium: без него Spotify не выдаёт ключ и не пускает на сторонние устройства Connect.
- Ключ личный: по правилам Spotify каждый пользователь создаёт свой.
- Громкость Spotify программная и не связана с громкостью Алисы.

## Сборка

Нужен Linux (или WSL) с `curl`, `dpkg-deb` и zig 0.15.1 (`python3 -m pip install ziglang==0.15.1`). Так же собирает CI, `.github/workflows/spotify.yml`:

```bash
bash plugins/spotify/build-runtime.sh
python3 plugins/spotify/build-plugin.py
```

`build-runtime.sh` скачивает пакеты Debian с закреплёнными версиями, сверяет SHA-256, собирает заглушку libpulse и кладёт всё в `service/runtime/`. Лицензии компонентов копируются в `licenses/runtime/`, контрольные суммы файлов runtime — в `licenses/runtime/SHA256SUMS`.
